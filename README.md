# FlyUp — Playwright JavaScript

แก้ไขจากรายงาน 6 failed ล่าสุด: ตั้ง session Booster เป็นค่าเริ่มต้นให้ LIVE-001 และ TC4-002 ด้วย และเปลี่ยนช่องจำนวนเงินเป็น textbox ชื่อ `สูงสุด <วงเงินปัจจุบัน>` ตาม error-context จริง จึงไม่ผูกกับยอด 6,600 เดิม การลองรันจากเครื่องมือผู้ช่วยติดข้อจำกัด `spawn EPERM` ตอนเปิด Chromium จึงยังไม่ยืนยันผลผ่านทั้งชุด ให้รัน `npm.cmd test` ใน terminal ของผู้ใช้

## การทำงานอัตโนมัติ (อัปเดตล่าสุด)

สคริปต์กดรับคุกกี้ตามชื่อปุ่มที่กำหนดไว้ ล็อกอินจาก .env ติ๊กยอมรับเงื่อนไข และกดดำเนินการชำระเงินเพื่อเปิดกล่องยืนยันอัตโนมัติแล้ว ไม่มี page.pause() หากปุ่มคุกกี้ชื่ออื่น ให้ตั้ง COOKIE_BUTTON_SELECTOR ตาม DOM จริง

บน www.fly-up.app สคริปต์จบที่กล่องยืนยันการลงทุน การกดยืนยันอัตโนมัติเพื่อเปิด QR รองรับเฉพาะระบบทดสอบที่ได้รับอนุญาต: ตั้ง BASE_URL และ SANDBOX_ORIGIN ให้เป็น origin เดียวกันของระบบทดสอบ, AUTO_CONFIRM_PAYMENT=true และ PAYMENT_QR_SELECTOR ให้ตรง DOM จริง ระบบไม่ใช้ origin production เป็น sandbox

การแสดง QR ไม่ใช่ผลการชำระเงินสำเร็จ ยังไม่มีการเชื่อม payment simulator หรือ assertion หลังจ่ายสำเร็จ ข้อความเดิมด้านล่างที่กล่าวถึงการกด Resume ใช้กับรุ่นเก่าและถูกแทนที่โดยพฤติกรรมข้างต้น

## ล็อกอินอัตโนมัติด้วย .env

เพิ่ม `.env` พร้อมข้อมูลบัญชีที่ผู้ใช้ให้มาแล้ว `npm.cmd install` จากนั้น `npm.cmd test` จะล็อกอิน Booster ใหม่อัตโนมัติ ตรวจอีเมลและบทบาท แล้วบันทึก session ก่อนเริ่มเทส ใช้ `npm.cmd run login` เพื่อทดสอบเฉพาะการล็อกอินได้

`.env` มีรหัสผ่านจริงและถูกเพิ่มใน .gitignore แล้ว ห้าม commit หรือส่ง ZIP ที่มีไฟล์นี้ให้ผู้อื่น หากจะแชร์โค้ดให้ลบ `.env` และใช้ `.env.example` แทน ตั้ง `AUTO_LOGIN=false` เมื่อต้องการใช้ขั้นตอนล็อกอินด้วยตนเอง

ตรวจ selector ฟอร์มล็อกอินจากเว็บจริงแล้ว (`input[name="email"]`, `input[name="password"]`) และทดลองส่งฟอร์มผ่าน browser automation ส่วนสคริปต์ Node ยังไม่ได้รันด้วย Playwright runner ในเครื่องนี้

ชุดทดสอบ UC4 ตามเอกสารแนบ ใช้เว็บจริง ไม่มี mock API และไม่กดยืนยันลงทุนหรือชำระเงิน

## เริ่มใช้งาน (PowerShell)

```powershell
cd <โฟลเดอร์ flyup-playwright>
npm.cmd install
npx.cmd playwright install chromium
npm.cmd test -- --grep 'LIVE-001|TC4-002'
```

ทดสอบด้วยบัญชี Booster:

```powershell
npm.cmd run login -- booster
npm.cmd run test:live
npm.cmd run report
```

คำสั่ง login เปิดเบราว์เซอร์ให้ล็อกอินเอง ตรวจบทบาท KYC และข้อมูลธนาคารให้ตรง precondition แล้วกด Enter ใน terminal เพื่อบันทึก session ส่วน Admin/เจ้าของใช้ `npm.cmd run login -- admin` หรือ `npm.cmd run login -- owner` ตามลำดับ บัญชี owner ต้องเป็นเจ้าของ ID22 จริง

เมื่อ Inspector หยุดที่ `page.pause()` ให้อ่านและยอมรับสัญญาด้วยตนเองในเบราว์เซอร์ ไปถึงหน้าระบุจำนวนเงินลงทุน แล้วกด Resume ภายในเวลา 3 นาที ทำซ้ำในแต่ละเทสที่ต้องใช้หน้าจำนวนเงิน

ปรับข้อมูลผ่าน environment variables เช่น:

```powershell
$env:BASE_URL = 'https://www.fly-up.app'
$env:PROJECT_ID = '51'
$env:PROJECT_NAME = 'storemate - เพื่อนคู่คลัง'
# กำหนดเฉพาะเมื่อพบ selector ช่องจำนวนเงินจริงจาก DevTools
# $env:AMOUNT_SELECTOR = 'input[name="actual-field-name"]'
```

## สถานะและขอบเขต

ตรวจหน้าเว็บจริงด้วย browser automation วันที่ 17 ต.ค. 2026 พบ storemate ID51 กำลังระดมทุน 33,400/40,000 บาท ขั้นต่ำ 400 สูงสุด 6,600 และเปิดหน้าเงื่อนไขได้ ยังไม่ได้รันชุดไฟล์นี้ด้วย Playwright Test runner และยังไม่ได้ตรวจส่วนหลังยอมรับสัญญาใน session ที่ล็อกอิน

ตัวเลือกหน้าโปรเจกต์และหน้าเงื่อนไขอ้างอิง UI ที่ตรวจจริง ส่วนช่องจำนวนเงิน ป้ายสรุป และ dialog อ้างอิงเอกสาร ต้องตรวจ/ปรับให้ตรง DOM จริงก่อนใช้งานเป็น regression suite ไม่ควรนับ skipped หรือผลบางส่วนเป็นผ่านทั้ง Test Case

| Test Case | สิ่งที่สคริปต์ตรวจ |
|---|---|
| TC4-001 | สรุปค่าธรรมเนียมและกล่องยืนยันบางส่วน ยังไม่ครอบคลุมผู้สนับสนุน ยอดรวม QR การจ่าย PDF อีเมล หรือรายการซ้ำ |
| TC4-002 | กลับจากหน้าเงื่อนไขและเทียบยอดโครงการ ยังไม่ตรวจประวัติ/การยกเลิกทุกขั้น |
| TC4-003 | จำนวนเงินผิด 4 แบบ แยกเทส ข้อมูลไม่เข้าเงื่อนไขให้ skip |
| TC4-004 | ยอดเศษ 10 บาทและเติม 6,600 อัตโนมัติ |
| TC4-005 | skip รอยืนยันข้อยกเว้น 2 กรณี |
| TC4-006 | ไปถึงกล่องยืนยันยอด 6,600 ยังไม่ตรวจหลังจ่าย |
| TC4-007 | skip รอยืนยันกติกา Soft Cap และ fixture |
| TC4-008 | skip รอบัญชีไม่ผ่าน KYC/ไม่มีธนาคารและ UI จริง |
| TC4-009 | ปุ่ม Admin ถูกปิดใช้งาน ต้องมี session ที่ตรวจบทบาทแล้ว |
| TC4-010 | ปุ่มเจ้าของถูกปิดใช้งาน ต้องมี session เจ้าของจริง |

รายงาน HTML อยู่ใน playwright-report ส่วน screenshot/video/trace ของเทสที่ fail อยู่ใน test-results ข้อมูลเหล่านี้และ .auth อาจมีข้อมูลบัญชี อย่าเผยแพร่ไฟล์ session

ยอดในระบบจริงเปลี่ยนได้ การเปรียบเทียบยอดก่อน/หลังอาจถูกรบกวนจากผู้ใช้คนอื่น ใช้โครงการทดสอบที่ควบคุมได้เมื่อต้องการผลที่ทำซ้ำได้ การตรวจ QR/ชำระสำเร็จ/PDF/อีเมล/ledger ต้องมีช่องทางจ่ายทดสอบและบัญชีที่ได้รับอนุญาตก่อนเพิ่ม assertion
